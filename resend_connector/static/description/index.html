Resend Email Connector

Send Odoo email through Resend, receive replies in the chatter and follow the delivery of every message without opening an SMTP port.

Author: POLISHCHUK & SONS LTD  |  License: LGPL-3  |  Odoo 19.0 and 20.0

What it does

Odoo continues to prepare email the usual way: quotations, invoices, chatter notifications, templates, mass mailings, attachments, Bcc and alias domains. The module changes only the transport. Instead of an SMTP connection, the message is sent to the Resend API over HTTPS, and the delivery events Resend reports are written back to the original Odoo record.

Main features

Every Odoo emailNotifications, documents, templates and mass mailings use the same transport. No other module needs to be changed.
Delivery statusSent, delivered, delayed, opened, clicked, bounced, complained or failed, with the Resend error text when something goes wrong.
Replies in the chatterIncoming messages are fetched from Resend and processed by Odoo's own mail gateway, so they arrive in the right thread.
Domains and DNSRegister a domain, see the SPF, DKIM and MX records, verify it and keep the status in sync.
Signed webhooksDelivery events are verified with the Svix signature, with replay protection and duplicate detection.
No mail portSending works over HTTPS on port 443, including on hosts that block ports 25, 465 and 587.

Getting started

  • Install the module and open Settings > Discuss > Resend.
  • Create a Resend API key, paste it in the settings and set the From address on a domain verified in Resend.
  • Tick Use Resend API on the outgoing mail server that Odoo should use.
  • Create the webhook from the settings screen. The Odoo instance must be reachable from the internet for this step.
  • Send an email and open Resend > Emails to see its status.
A detailed guide for administrators and end users is included in the module: Resend > Documentation, and in the doc folder (English and Russian).

Incoming mail

Reply handling uses the receiving side of Resend. Publish the MX record of a subdomain, point the Odoo alias domain to it and let Resend deliver the messages. The module downloads the original message from Resend, restores the references to the Odoo thread and passes it to Odoo's mail gateway. Messages that do not match an alias stay available in Resend > Inbound.

Good to know

  • Resend sends its own Message-Id. The module keeps the value and maps replies back to the Odoo message, so threading works with any mail client.
  • Sending is idempotent: a retry cannot deliver the same email twice.
  • The module respects the Resend rate limit of 10 requests per second and slows down mass mailings instead of dropping messages.
  • Some mail servers place Resend email in spam if the domain is not authenticated. Publish SPF, DKIM and a DMARC record.

Requirements

Odoo 19.0 or 20.0, a Resend account and, for production sending, a domain verified in Resend. The module uses the requests library that ships with Odoo, so no extra Python package is needed.
