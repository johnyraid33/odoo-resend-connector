# Resend Email Connector: руководство по установке и настройке

Это руководство описывает установку и настройку модуля Resend Email Connector для
Odoo. Оно рассчитано на администраторов, которые раньше не работали с Resend, и на
пользователей, которым нужно только посмотреть статус письма.

Версия модуля 1.0.0. Odoo 19.0 и 20.0. Автор: POLISHCHUK & SONS LTD,
https://rex.cy.

## 1. О модуле

Обычно Odoo отправляет письма через SMTP. На практике это даёт три проблемы:
многие хостинги блокируют SMTP-порты, SMTP сообщает только о том, что сервер принял
письмо, а ответы клиентов остаются в почтовом ящике, а не в карточке Odoo.

Модуль отправляет всю почту Odoo через Resend по HTTPS. Odoo продолжает
формировать письмо как обычно: шаблоны, вложения, скрытые копии, домены алиасов.
Resend доставляет письмо и сообщает результат: доставлено, открыто, отклонено и
так далее. Входящие письма также можно принимать через Resend и передавать в
почтовый шлюз Odoo, тогда ответы появляются в чате карточки.

Модуль добавляет в Odoo отдельный раздел Resend. Другие модули менять не нужно.

## 2. Перед началом

Проверьте следующее:

* Odoo 19.0 или 20.0 работает, и вы можете войти как администратор.
* У вас есть доступ к DNS-записям домена, с которого будет отправляться почта. Как
  правило, это панель хостинга или регистратора.
* У Odoo есть адрес, доступный из интернета, например https://odoo.example.com.
  Он нужен для webhook доставки. Если Odoo запущен на локальном компьютере, для
  теста можно использовать временный туннель.
* Есть аккаунт на https://resend.com. Для проверки достаточно бесплатного плана.
* Выбрано, с какого адреса отправлять письма, например no-reply@mg.example.com.

Желательно использовать отдельный поддомен для почты, например mg.example.com или
mail.example.com. Тогда репутация этого поддомена не зависит от основного домена
сайта.

## 3. Аккаунт Resend и API-ключ

1. Откройте https://resend.com и создайте аккаунт.
2. Откройте раздел API Keys и нажмите Create API Key.
3. Выберите уровень доступа:
   * Sending access: достаточно для отправки писем.
   * Full access: также позволяет модулю управлять доменами и webhook из Odoo.
   Выберите Full access, если хотите регистрировать домены и создавать webhook прямо
   в настройках Odoo.
4. Скопируйте ключ. Он начинается с re_.
5. Сохраните ключ в надёжном месте. Resend показывает его только один раз.

Ключ вводится в Odoo позже, в разделе Settings > Discuss > Resend.

## 4. Добавление и проверка домена

Resend отправляет письма только с проверенных доменов. Проверка подтверждает, что
домен принадлежит вам, и включает SPF и DKIM. По этим записям почтовые серверы
получателей решают, можно ли доверять письму.

### 4.1 Добавление домена

Это можно сделать двумя способами.

Из Odoo:

1. Откройте Resend > Domains и нажмите New.
2. Укажите домен, например mg.example.com. Поле Region оставьте пустым, если Resend
   не предложил выбрать регион.
3. Нажмите Register in Resend.
4. В форме появятся DNS-записи, которые сгенерировал Resend.

Из панели Resend:

1. Откройте Domains и нажмите Add Domain.
2. Укажите домен и нажмите Add.
3. Скопируйте записи в Odoo: Resend > Domains, откройте домен и нажмите
   Synchronise.

### 4.2 Публикация DNS-записей

Откройте панель DNS вашего провайдера и добавьте записи точно так, как они
показаны. Обычно их три:

| Тип | Имя | Значение | Назначение |
|---|---|---|---|
| TXT | send (или имя из Resend) | v=spf1 include:amazonses.com ~all | SPF: разрешает Resend отправлять от имени домена |
| TXT | resend._domainkey | длинный ключ, начинается с p= | DKIM: подписывает каждое письмо |
| MX | send (только для входящей почты) | feedback-smtp.<регион>.amazonses.com | Возвращает отказы в Resend |

Resend также рекомендует запись DMARC. Она сообщает серверам получателей, что
делать при ошибке SPF или DKIM, и куда отправлять отчёты. Начать можно с такой
записи:

| Тип | Имя | Значение |
|---|---|---|
| TXT | _dmarc | v=DMARC1; p=none; rua=mailto:dmarc@example.com |

Замените example.com на свой домен и укажите адрес, который вы читаете.

Некоторые DNS-провайдеры просят указывать имя без домена. Например, для
send.mg.example.com панель может ожидать только send. Если провайдер сам добавляет
домен, введите короткое имя. Если нет, введите полное.

### 4.3 Проверка

1. В Odoo откройте Resend > Domains и откройте домен.
2. Нажмите Verify Now.
3. Если статус остаётся Pending, подождите несколько минут. Изменения DNS могут
   занимать от нескольких минут до нескольких часов.
4. Нажмите Synchronise, чтобы обновить статус.

Когда всё верно, статус становится Verified, а домен появляется в списке
проверенных доменов в Settings > Discuss > Resend.

Если проверка не проходит, сравните каждую запись посимвольно. Ошибкой может быть
лишняя кавычка, неверное имя или пробел. Можно также открыть домен в панели Resend:
там видно, какая запись не найдена.

### 4.4 Домен для приёма писем (только для входящей почты)

Если ответы должны приходить через Resend, включите приём для домена или добавьте
второй домен только для ответов, например reply.example.com. Для приёма Resend
нужна MX-запись. Если основной домен уже принимает почту, например через Google
Workspace или Microsoft 365, используйте для ответов поддомен: вторая MX-запись на
основном домене конфликтует с существующим почтовым ящиком.

## 5. Установка модуля в Odoo

### 5.1 Обычная установка

1. Скопируйте папку resend_connector в каталог addons вашего сервера Odoo.
2. Перезапустите службу Odoo.
3. Откройте Apps, нажмите Update Apps List и найдите Resend Email Connector.
4. Нажмите Install.

### 5.2 Установка в Docker

Добавьте папку модуля как том в docker-compose.yml:

    services:
      odoo:
        volumes:
          - ./resend_connector:/mnt/extra-addons/resend_connector

Затем перезапустите контейнер и установите модуль из Apps или выполните:

    docker compose exec odoo odoo -d odoo -i resend_connector --stop-after-init

### 5.3 После установки

В главном меню появляется приложение Resend. Оно видно пользователям группы Resend
Manager. Администраторы входят в эту группу автоматически. Остальных пользователей
можно добавить в Settings > Users.

## 6. Настройка исходящей почты

Откройте Settings > Discuss > Resend.

### 6.1 Общий переключатель

Включите Send emails through Resend. Когда переключатель выключен, вся почта снова
идёт через SMTP, даже на серверах, помеченных как Resend. Это быстрый способ
отключить модуль без удаления.

### 6.2 API-ключ

Вставьте ключ, созданный в разделе 3. Он хранится как системный параметр, и его
могут читать только администраторы.

### 6.3 Адрес отправителя

Укажите адрес на проверенном домене, например no-reply@mg.example.com.

### 6.4 Подмена отправителя

Odoo выбирает адрес отправителя по пользователю, компании или алиасу. Часто этот
адрес относится к домену, который Resend не знает. Настройка Rewrite From
определяет поведение:

* Only when the sender domain is not verified in Resend (рекомендуется): модуль
  заменяет отправителя на адрес из настройки только тогда, когда исходный домен
  отсутствует в списке проверенных. Исходный адрес сохраняется в Reply-To, поэтому
  ответы по-прежнему приходят нужному человеку.
* Always: все письма отправляются с указанного адреса.
* Never: модуль отправляет адрес, выбранный Odoo. Resend отклонит письмо с
  незнакомого домена.

### 6.5 Исходящий почтовый сервер

Откройте Settings > Technical > Outgoing Mail Servers и откройте сервер, который
использует Odoo. Включите Use Resend API. Поля SMTP для этого сервера не
используются, но Odoo требует заполнить хост и порт; можно оставить текущие
значения.

Нажмите Test Connection. Модуль проверит API-ключ и покажет количество доменов,
которые вернул Resend.

Если серверов несколько, включите настройку только там, где нужен Resend.
Остальные продолжат работать через SMTP.

### 6.6 Дополнительные настройки

Откройте раздел Advanced в Settings > Discuss > Resend. Значения по умолчанию
подходят для большинства установок. Все параметры описаны в разделе 14.

## 7. Тестовое письмо

### 7.1 Из документа

Откройте любую заявку, счёт или контакт, нажмите Send и выберите Email. Письмо
готовится в Odoo как обычно и отправляется через Resend.

Откройте Resend > Emails. Новая строка показывает тему, получателей, идентификатор
письма Resend и статус. Сначала статус Sent. После настройки webhook он меняется на
Delivered, Opened или статус ошибки.

### 7.2 Тестовые адреса

Resend предоставляет адреса, которые имитируют результаты доставки. Они полезны для
проверки статусов без отправки реальным получателям:

| Адрес | Результат |
|---|---|
| delivered@resend.dev | Доставлено |
| bounced@resend.dev | Жёсткий отказ |
| complained@resend.dev | Доставлено, затем помечено как спам |
| suppressed@resend.dev | Подавлено, письмо не отправлено |

Без проверенного домена Resend принимает отправителя только onboarding@resend.dev и
отправляет только на адрес вашего аккаунта или на эти тестовые адреса. После
проверки домена тестовые адреса продолжают работать, и можно использовать любого
реального получателя.

Каждое тестовое письмо расходует квоту Resend.

### 7.3 Мастер тестового письма

Откройте Settings > Discuss > Resend и нажмите Send a test email. Мастер отправит
письмо через полный путь Odoo и покажет результат.

## 8. Настройка webhook доставки

Webhook это способ, которым Resend сообщает Odoo, что произошло с письмом. Без них
модуль не показывает статусы доставки, отказа и жалобы. Статус может обновляться и
задачей сверки по расписанию, но обычный путь это webhook.

### 8.1 Требования

Odoo должен быть доступен из интернета по публичному HTTPS-адресу. Этот адрес
используется в URL webhook:

    https://odoo.example.com/resend/webhook

Если Odoo стоит за прокси, адрес должен быть публичным, а прокси должен передавать
запрос в Odoo.

### 8.2 Автоматическое создание

1. В Settings > Discuss > Resend проверьте Webhook URL в разделе Delivery
   webhooks.
2. Если адрес неверный, укажите Public Base URL, публичный адрес экземпляра.
3. Нажмите Create / update webhook in Resend.
4. Модуль создаст endpoint в Resend, подпишет его на события почты и сохранит
   секрет подписи. Рядом с кнопкой появится Secret configured.

### 8.3 Ручное создание

Если вы предпочитаете создать endpoint в панели Resend:

1. Откройте Webhooks в Resend и нажмите Add Endpoint.
2. Вставьте URL из Odoo.
3. Выберите события: email.sent, email.delivered, email.delivery_delayed,
   email.opened, email.clicked, email.bounced, email.complained, email.failed,
   email.suppressed и email.received.
4. Скопируйте секрет подписи, он начинается с whsec_, и вставьте его в Settings >
   Discuss > Resend > Webhook Signing Secret.
5. Сохраните.

Секрет может содержать несколько значений через запятую. Это удобно при смене
секрета.

### 8.4 Проверка событий

Откройте Resend > Configuration > Webhook Events. Каждый вызов Resend появляется
там с типом и статусом. Если включён Store Webhook Payloads, сохраняется и тело
запроса для отладки.

Если список пуст, экземпляр недоступен из интернета, webhook не подписан на
события или неверный секрет.

## 9. Приём входящей почты

Приём необязателен. Настройте его, если ответы должны появляться в чате.

### 9.1 DNS

Добавьте MX-запись для приёма на поддомене. В Resend откройте домен, включите
Receiving, если он выключен, и скопируйте MX-запись. Опубликуйте её у DNS-провайдера.
Resend принимает почту только тогда, когда его MX-запись имеет наименьший
приоритет для этого имени.

### 9.2 Домен алиасов в Odoo

1. Откройте Settings > Discuss.
2. Укажите Alias Domain, например reply.example.com.
3. Сохраните.

После этого Odoo использует этот домен для алиасов и для адреса Reply-To исходящих
писем.

### 9.3 Создание алиаса

Алиас связывает почтовый адрес с моделью Odoo. Например,
sales@reply.example.com может создавать лиды.

1. Откройте Settings > Technical > Email > Aliases и нажмите New.
2. Укажите имя, например sales.
3. Выберите модель, например CRM Lead.
4. Сохраните.

Алиасы также можно настраивать в настройках самого приложения, например в Sales,
в зависимости от установленных модулей.

Resend принимает любой адрес на домене приёма, поэтому создавать ящики в Resend не
нужно. Маршрутизацией занимается Odoo.

### 9.4 Ответы на существующее письмо

Когда клиент отвечает на письмо, отправленное из Odoo, сообщение содержит ссылку на
исходное письмо. Модуль восстанавливает эту ссылку, и Odoo прикрепляет ответ к той же
карточке и ветке, без алиаса.

### 9.5 Проверка входящих

Откройте Resend > Inbound. Каждое полученное письмо показывается с отправителем,
получателем и статусом:

* Processed: письмо передано в карточку Odoo.
* No Route: получатель не совпал ни с алиасом, ни с веткой. Откройте письмо, чтобы
  увидеть причину, создайте нужный алиас и нажмите Process Again.
* Pending: ожидание API Resend. Задача по расписанию повторит попытку.
* Failed: смотрите текст ошибки в записи.

## 10. Повседневная работа

### 10.1 Меню Resend

* Emails: все письма, отправленные через Resend, со статусом и историей событий.
* Inbound: письма, полученные от Resend.
* Domains: домены отправки, их статус и DNS-записи.
* Configuration > Settings: настройки.
* Configuration > Webhook Events: вызовы от Resend.
* Configuration > Delivery Events: события доставки по письмам.
* Documentation: это руководство внутри Odoo.

### 10.2 Как читать статус

Откройте письмо в Resend > Emails, чтобы увидеть статус и список событий. Тот же
статус показывается в стандартной записи письма в Settings > Technical > Emails и
в связанном документе.

Если письмо не отправлено, причина от Resend сохраняется в поле ошибки и в причине
сбоя письма Odoo. Типичные причины: непроверенный домен, неверный API-ключ,
заблокированный тип вложения или исчерпанная квота.

### 10.3 Повтор неудачного письма

Откройте письмо в Resend > Emails и нажмите Retry in Odoo. Модуль вернёт письмо в
очередь Odoo. Автоматические повторы также выполняются для временных ошибок, таких
как сбои сети, ограничение частоты и ошибки сервера, до заданного предела.

### 10.4 Домены

Нажмите Synchronise на домене, чтобы обновить статус и DNS-записи. Задача по
расписанию делает это раз в день.

## 11. Решение проблем

| Проблема | Что проверить |
|---|---|
| Письмо не отправлено, в причине упоминается Resend API | Прочитайте ошибку в письме. Неверный API-ключ: создайте новый. Домен не проверен: завершите раздел 4. Квота: подождите или смените план Resend. |
| Письма уходят, но статус не меняется | Откройте Resend > Configuration > Webhook Events. Если пусто, настройте webhook (раздел 8) и проверьте доступность Odoo из интернета. |
| Webhook отвечает 401 | Секрет подписи в Odoo не совпадает с секретом в Resend. Скопируйте его заново. Проверьте часы сервера, допуск пять минут. |
| Ответы не появляются в чате | Проверьте MX-запись, подписку email.received, Alias Domain и список Resend > Inbound. |
| Resend отклоняет вложение | Resend блокирует исполняемые типы файлов. Переименуйте или заархивируйте файл либо отправьте ссылку. |
| Массовая рассылка идёт медленно | Resend разрешает 10 запросов в секунду на команду. Модуль ограничивает себя 8 и повторяет остальные, поэтому рассылка идёт дольше, но письма не теряются. |
| Endpoint отключён со стороны Resend | Resend отключает endpoint, который долго отвечает ошибками. Исправьте URL или проверку подписи и включите или создайте endpoint заново. |

Подробности есть в журнале Odoo. Ищите resend_connector и resend webhook.

## 12. Безопасность и конфиденциальность

* API-ключ и секрет подписи хранятся как системные параметры. Их видят только
  пользователи группы Settings, в журнал они не записываются.
* Каждый вызов webhook проверяется по подписи Svix с постоянным временем сравнения
  и допуском пять минут. Повторные вызовы с тем же идентификатором игнорируются.
* Для отправки используется ключ идемпотентности на каждое письмо Odoo, поэтому
  повтор не может доставить письмо дважды.
* Вложения проверяются по списку запрещённых Resend типов и по ограничению размера
  до отправки.
* Входящие письма обрабатываются почтовым шлюзом Odoo, который применяет обычные
  правила доступа и работу с вложениями.
* Содержимое и метаданные писем хранятся в Resend согласно настройкам вашего
  аккаунта. Если есть требования к месту хранения данных, изучите документацию
  Resend.

## 13. Удаление

При удалении модуль удаляет свои модели (письма, события, домены, входящие) и
настройки. Уже отправленные письма остаются в панели Resend. Стандартные записи
mail.mail в Odoo сохраняются.

Перед удалением верните исходящие серверы на SMTP, иначе Odoo останется без
почтового сервера.

## 14. Приложение: настройки

| Настройка | По умолчанию | Описание |
|---|---|---|
| Send emails through Resend | выкл | Общий переключатель. Когда выключен, почта идёт через SMTP. |
| Resend API Key | пусто | API-ключ из Resend. |
| From Address | пусто | Адрес отправителя на проверенном домене. |
| Rewrite From | только если не проверен | Заменяет отправителя, если его домен не проверен в Resend. |
| Webhook URL | вычисляется | Адрес, который вызывает Resend. Строится из Public Base URL или адреса Odoo. |
| Webhook Signing Secret | пусто | Секрет из Resend для проверки вызовов. |
| Inline Images | content id | Как отправлять встроенные изображения. Content id сохраняет ссылки cid; data uri встраивает изображение в HTML; attachment отправляет его обычным файлом. |
| Send Odoo Message-ID | вкл | Добавляет Message-Id Odoo в заголовки. Resend всё равно назначает свой идентификатор, модуль отслеживает оба. |
| Store Webhook Payloads | вкл | Сохраняет тело webhook для отладки. |
| Keep Original Inbound Messages | выкл | Прикрепляет файл исходного письма к входящим. |
| Auto-Retry Transient Failures | 3 | Число автоматических повторов для временных ошибок. Ноль отключает повторы. |
| Retry Delay (minutes) | 15 | Задержка между автоматическими повторами. |
| Requests / second | 8 | Ограничение частоты запросов к Resend. Resend разрешает 10 на команду. |
| Webhook Tolerance (seconds) | 300 | Допустимое расхождение часов для подписи webhook. |
| API Base URL | https://api.resend.com | Менять только для прокси или тестового сервера. |
| Public Base URL | пусто | Публичный адрес экземпляра для URL webhook. |

## 15. Приложение: события webhook

| Событие | Значение |
|---|---|
| email.sent | Resend принял письмо |
| email.delivered | Сервер получателя принял письмо |
| email.delivery_delayed | Resend повторяет доставку |
| email.opened | Получатель открыл письмо (нужен трекинг) |
| email.clicked | Получатель перешёл по ссылке (нужен трекинг) |
| email.bounced | Письмо отклонено |
| email.complained | Получатель пометил письмо как спам |
| email.failed | Resend не смог отправить письмо |
| email.suppressed | Адрес находится в списке подавления |
| email.received | Resend получил письмо для домена приёма |
